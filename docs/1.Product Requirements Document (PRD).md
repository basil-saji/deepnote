# Executive Summary

DeepNote is an offline AI-powered semantic note-taking application developed as the course project for Object-Oriented Programming using Java. Unlike traditional note-taking applications that rely only on keyword matching, DeepNote enables users to search notes by meaning using locally generated vector embeddings.

Notes are stored as standard TXT files to preserve portability and user ownership, while PostgreSQL with the pgvector extension stores only metadata and semantic index information required for efficient search. Ordinary semantic search remains separate from an optional local AI chat assistant. When the user opens the assistant from a note editor, it answers questions grounded in that active note using a local generative model; it does not search the entire note collection in the first version.

# Problem Statement

Traditional note-taking applications depend mainly on keyword-based search. Users often remember concepts rather than exact words, making note retrieval inefficient.

DeepNote solves this problem by generating vector embeddings for note contents and performing semantic similarity search locally without requiring cloud services. After opening a note, users can optionally open a collapsible AI sidebar to ask questions about that note without copying its contents to a cloud chatbot.

---

# Product Vision

To develop a lightweight, offline-first desktop application that combines portable plain-text note-taking, fast semantic search and optional local AI assistance grounded in the currently open note while preserving user privacy, portability and ownership of data.

# AI Chat Workflow — Active Note Only

Open a note in the editor

↓

Open the AI sidebar

↓

Capture the active editor buffer and note title

↓

Combine note content, a bounded number of recent conversation turns and the question

↓

Check the configured context budget

↓

Call a local generative model through Ollama in a background worker

↓

Display the answer in the sidebar


The first implementation does not use pgvector or SearchService for AI chat. If the note is too long to fit, it must display a clear message or use a deliberate bounded-context strategy; it must not silently truncate the note while claiming to have considered the whole document.

# Engineering Principles

1. TXT files are the primary source of truth.

2. PostgreSQL stores only metadata and semantic index information.

3. Semantic search is the preferred retrieval mechanism.

4. Keyword search is automatically used when semantic search is unavailable.

5. Indexing must never block the user interface.

6. Re-index only when the note content changes.

7. External libraries should simplify implementation without tightly coupling the application to a specific framework.

8. AI chat is optional and scoped to the active note in its first version.

9. Use the current editor buffer where feasible so unsaved edits are not silently omitted.

10. Keep chat generation off the Swing Event Dispatch Thread.

11. Every design decision should remain easy to explain during project evaluation.
