# Executive Summary

DeepNote is an offline-first note-taking application developed as the course project for Object-Oriented Programming using Java. The current foundation provides portable TXT notes, local keyword search and optional active-note Ollama chat. Semantic/vector search is planned for the later database phase and is not current functionality.

Notes are stored as standard TXT files to preserve portability and user ownership. PostgreSQL and pgvector are future infrastructure for semantic indexing and ranking; they are not required by the current foundation. Ordinary local keyword search remains separate from optional local AI chat. When the user opens the assistant from a note editor, it answers questions grounded in that active note using Ollama; it does not search the entire note collection.

# Problem Statement

Traditional note-taking applications depend mainly on keyword-based search. Users often remember concepts rather than exact words, making note retrieval inefficient.

DeepNote first solves reliable local note storage and keyword retrieval without cloud services. A later database phase will add verified vector search. After opening a note, users can optionally open a collapsible right-side AI panel to ask questions about that note without copying its contents to a cloud chatbot.

---

# Product Vision

To develop a lightweight, offline-first desktop application that combines portable plain-text note-taking, local keyword search and optional local AI assistance grounded in the currently open note, while leaving semantic ranking for the later database phase.

## UI and Navigation Target

The target UI uses Java 25 LTS, JavaFX 27, AtlantaFX 3.0.0, FXML for larger layouts, Java controllers, centralized JavaFX CSS/design tokens, and Maven. The JavaFX smoke foundation exists; the complete wireframe migration remains planned.

There is no left sidebar, navigation rail, drawer, sidebar toggle, hidden panel or reserved navigation column. The homepage is the sole note-browsing interface. Following the wireframe, it contains the greeting/header, settings action, integrated search, category/tag filters only when supported by actual data, a functional list/grid toggle, Recents, Notes and New Note. No placeholder data or nonfunctional controls are considered implemented.

The application opens on the homepage. The `+` action opens a new Home tab. Selecting a note from a Home tab replaces that tab's content with the note editor. If the note is already open in another tab, its existing tab is activated. Notes remain accessible in top-level tabs; tabs can be closed and a new Home tab can be opened. The optional AI assistant is a collapsible panel on the right of the active editor, grounded in the active editor buffer with separate in-memory conversation history per note. Ollama calls run in JavaFX background work and never block the JavaFX Application Thread.

# AI Chat Workflow — Active Note Only

Open a note in the editor

↓

Open the right-side AI panel

↓

Capture the active editor buffer and note title

↓

Combine note content, a bounded number of recent conversation turns and the question

↓

Check the configured context budget

↓

Call a local generative model through Ollama in a background worker

↓

Display the answer in the right-side panel


The first implementation does not use pgvector or SearchService for AI chat. If the note is too long to fit, it must display a clear message or use a deliberate bounded-context strategy; it must not silently truncate the note while claiming to have considered the whole document.

# Engineering Principles

1. TXT files are the primary source of truth.

2. In the planned database phase, PostgreSQL stores only metadata and semantic index information.

3. Local keyword search is the current retrieval mechanism; semantic search is planned.

4. Do not claim keyword fallback or semantic ranking until the corresponding database path is implemented and verified.

5. Indexing (planned database phase) must never block the user interface.

6. In the planned database phase, re-index only when the note content changes.

7. External libraries should simplify implementation without tightly coupling the application to a specific framework.

8. AI chat is optional and scoped to the active note in its first version.

9. Use the current editor buffer where feasible so unsaved edits are not silently omitted.

10. Keep chat generation off the JavaFX Application Thread; run it in a JavaFX `Task`/`Service` and update the UI from Application-Thread callbacks.

11. Every design decision should remain easy to explain during project evaluation.
