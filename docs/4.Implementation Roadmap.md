Implement automatic semantic indexing.

Workflow

```text

↓

↓

↓

Content Changed?

↓

No → Finish

↓

Yes

↓

Launch SwingWorker

↓

Chunk Note

↓

Generate Embeddings

↓

Update PostgreSQL

↓

Update Stored Hash

↓

Display Status
```

Responsibilities

- Keep UI responsive
- Skip unnecessary indexing
- Update vectors only when content changes

---

## Deliverable Class — IndexWorker

`IndexWorker` (extends `SwingWorker`) is the concrete class that carries out this workflow in the background.

Responsibilities

- Run chunking and embedding generation off the EDT
- Delegate hash comparison and database updates to `IndexService`
- Track whether an indexing pass is currently running
- If a save arrives while `IndexWorker` is already running, set `pendingIndex = true` instead of starting a second worker
- On completion, check `pendingIndex`; if true, clear it and start a new `IndexWorker` run using the latest saved content

This is the class responsible for Repeated Save Handling (see SDD §8.1) — at most one `IndexWorker` runs at a time, and at most one additional run is ever pending.

# 13.1 Phase 9 — Local AI Chat for the Active Note

### Goal

Add an optional, collapsible chat sidebar to the note editor. A user opens a note, opens the sidebar if needed, and asks questions grounded in that note.

### Scope for the first version

- Use the active editor buffer and note title as grounding context; prefer current buffer text so unsaved edits are not ignored.
- Use a separate local generative/instruct model through Ollama. EmbeddingGemma remains the embedding model for semantic search.
- Keep regular semantic search fast and unchanged; do not invoke the chat model for an ordinary search.
- Keep a bounded number of recent conversation turns in memory for follow-up questions.
- Support one note per conversation. Keep state isolated per note or explicitly reset it when changing notes.
- Check context limits. For an oversized note, show a clear limitation or use a deliberate bounded-context strategy; do not silently truncate.
- Run model requests using SwingWorker or an equivalent background executor.
- No chat database tables, persistent history, whole-library retrieval or cloud fallback in the MVP.

### Suggested implementation order

1. Verify a small local chat model runs through Ollama.
2. Implement ChatModelClient and test local request/response handling.
3. Implement ContextManager and the grounding prompt.
4. Implement AIAssistantService.
5. Build AIAssistantPanel with message history, input, loading/error states and collapse control.
6. Connect the panel using AIAssistantController.
7. Ensure background execution, EDT updates and conversation isolation.
8. Test follow-ups, unsaved edits, empty/long notes, missing model, timeout, switching tabs, and collapse/reopen behavior.

### Acceptance criteria

- Assistant is only invoked by an explicit editor action.
- Answers are grounded in the active note; insufficient context is acknowledged.
- The sidebar can collapse/reopen without losing the current session conversation.
- The user interface remains responsive during inference.
- Errors do not break editing or semantic search.
- Existing database schema stays unchanged.

# 15. Package Responsibilities

## model

Application data models.

---

## dao

Database communication using JDBC.

---

## service

Contains `NoteService` and `CategoryService` — core note and category business logic.

---

## search

Contains the search subsystem:

```
search
    SearchService
    Searcher
    VectorSearcher
    TextSearcher
    SearchResult
```

- `Searcher` is the common interface for all search algorithms.
- `VectorSearcher` implements semantic search using embeddings and pgvector.
- `TextSearcher` implements keyword search as the fallback.
- `SearchService` delegates to the appropriate implementation at runtime and returns ranked `SearchResult` objects.

---

## indexing

Contains the indexing subsystem:

```
indexing
    IndexService
    IndexWorker
```

- `IndexService` coordinates hash comparison, chunking, and embedding generation.
- `IndexWorker` (a `SwingWorker`) runs indexing in the background and implements Repeated Save Handling.

---

## controller

Coordinates UI and services.

---

## ui

Swing user interface.

---

## util

Common utility classes.

---

## config

Application configuration.

---

## exception

Custom application exceptions.

```
exception
    NoteIndexingException
```

`NoteIndexingException` represents failures during semantic indexing, letting the UI show a meaningful message while note editing continues normally.
