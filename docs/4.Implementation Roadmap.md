# 1. Introduction

This roadmap outlines the development plan for DeepNote v0.1. It provides the recommended coding sequence, package organization, milestones, and implementation strategy.

The objective is to build the project incrementally so that every phase produces a working application before introducing the next feature.

```text
com.deepnote
├── DeepNoteApplication        legacy Swing launcher (transitional)
├── model/        Note, ChatMessage
├── service/      NoteService, LocalSearchService
├── ai/           AIAssistantService, ContextManager,
│                 ChatModelClient, OllamaChatModelClient

├── exception/    ChatModelException, ContextLimitException,
│                 NoteStorageException
├── fx/           DeepNoteFxApplication, FoundationController

│                  src/main/resources/com/deepnote/fx/)
└── ui/           MainWindow, AIAssistantPanel and Swing helpers
```

Target structure after the JavaFX migration (the same packages plus the `fx` sub-packages; `ui` and the Swing launcher are retired once the JavaFX shell is verified):

```text
com.deepnote
├── model/
├── service/
├── ai/
├── config/
├── exception/
└── fx/
    ├── view/         FXML views and reusable view components
```

Additional packages created only in the later database phase: `dao/`, `search/`, `indexing/` and `util/`. They do not exist today and are not needed by the current TXT-backed application.

Notes are stored as plain `.txt` files in `~/DeepNote/notes` by default (override with `-Ddeepnote.notesDir`).

# 11. Phase 6 — Local AI Chat for the Active Note and AI-Panel Migration

### Goal

Add an optional, collapsible right-side AI panel to the note editor. A user opens a note, opens the panel if needed, and asks questions grounded in that note.

### Scope for the first version

- Use the active editor buffer and note title as grounding context; prefer current buffer text so unsaved edits are not ignored.
- Use a separate local generative/instruct model through Ollama. EmbeddingGemma remains a planned embedding model, not a current chat model.
- Keep local keyword search independent from the chat model; semantic ranking is a later-phase concern.
- Keep a bounded number of recent conversation turns in memory for follow-up questions.
- Support one note per conversation. Keep state isolated per note or explicitly reset it when changing notes.
- Check context limits. For an oversized note, show a clear limitation or use a deliberate bounded-context strategy; do not silently truncate.
- Run model requests using JavaFX `Task`/`Service` (the legacy Swing panel uses its own worker until retired).
- No chat database tables, persistent history, whole-library retrieval or cloud fallback in the MVP.

### Suggested implementation order

1. Verify a small local chat model runs through Ollama. (Configured by `AppConfig`; default model `qwen2.5:0.5b`.)
2. `ChatModelClient` and `OllamaChatModelClient` — already implemented.
3. `ContextManager` and the grounding prompt — already implemented.
4. `AIAssistantService` — already implemented and unit-tested.
5. Build the JavaFX AI-panel view (message history, input, loading/error states, collapse control). The Swing `AIAssistantPanel` is legacy reference only.
6. Connect the panel with a JavaFX `AIAssistantController` in `fx.controller`.
7. Run model requests in a JavaFX `Task`/`Service`; apply results on the JavaFX Application Thread; keep conversation state isolated per note.
8. Test follow-ups, unsaved edits, empty/long notes, missing model, timeout, switching tabs, and collapse/reopen behavior.

### Acceptance criteria

- Assistant is only invoked by an explicit editor action.
- Answers are grounded in the active note; insufficient context is acknowledged.
- The right-side AI panel can collapse/reopen without losing the current session conversation.
- The user interface remains responsive during inference.
- Errors do not break editing or local keyword search.
- No database is required or touched; the chat works with PostgreSQL absent.

# 14. Phase 9 — Automatic Semantic Indexing (later database phase)

Implement automatic semantic indexing only after PostgreSQL/pgvector setup.

Workflow

```text
User Saves Note

↓

Write TXT File

↓

SHA-256 Hash

↓

Content Changed?

↓

No → Finish

↓

Yes

↓

Launch JavaFX Task/Service (planned database phase)

↓

Chunk Note

↓

Generate Embeddings

↓

Update PostgreSQL

↓

Update Stored Hash

↓

Display Status
```

Responsibilities

- Keep UI responsive
- Skip unnecessary indexing
- Update vectors only when content changes

---

## Deliverable Class — IndexWorker

The future JavaFX indexing task is the background component that will carry out this workflow.

Responsibilities

- Run chunking and embedding generation off the JavaFX Application Thread
- Delegate hash comparison and database updates to `IndexService`
- Track whether an indexing pass is currently running
- If a save arrives while `IndexWorker` is already running, set `pendingIndex = true` instead of starting a second worker
- On completion, check `pendingIndex`; if true, clear it and start a new `IndexWorker` run using the latest saved content

This is the class responsible for Repeated Save Handling (see SDD §8.1) — at most one `IndexWorker` runs at a time, and at most one additional run is ever pending.

# 17. Package Responsibilities

## model

Application data models. Currently `Note` and `ChatMessage`.

---

## dao (planned database phase)

Database communication using JDBC. Does not exist yet.

---

## service

Currently contains `NoteService` (TXT persistence) and `LocalSearchService` (local keyword search). `CategoryService` is planned and arrives with category support.

---

## ai

Contains `AIAssistantService`, `ContextManager`, `ChatModelClient` and `OllamaChatModelClient` — active-note chat grounding and the local model client. Independent of the search and indexing packages.

---

## search (planned database phase)

Proposed search subsystem. It does not exist yet; current keyword search is `service.LocalSearchService`:

```
search
    SearchService
    Searcher
    VectorSearcher
    TextSearcher
    SearchResult
```

- `Searcher` is the common interface for all search algorithms.
- `VectorSearcher` will implement semantic search using embeddings and pgvector in the later database phase.
- `TextSearcher` is the proposed database-phase keyword searcher; it may wrap `LocalSearchService` and serves as the fallback for FR-12.
- `SearchService` and ranked `SearchResult` objects are planned for the database phase.

---

## indexing (planned database phase)

Proposed indexing subsystem (does not exist yet):

```
indexing
    IndexService
    IndexWorker
```

- `IndexService` coordinates hash comparison, chunking, and embedding generation.
- The future JavaFX indexing task runs indexing in the background and implements Repeated Save Handling.

---

## fx

JavaFX target UI. Currently holds `DeepNoteFxApplication` and `FoundationController`. Target sub-packages: `fx.view` (FXML and views), `fx.controller` (Home, editor-tab and AI-panel controllers) and `fx.theme` (CSS/design tokens). There is no separate top-level `controller` package.

---

## ui (transitional legacy)

The existing Swing implementation (`MainWindow`, `AIAssistantPanel` and helpers). Legacy material only; retired once the JavaFX shell is verified.

---

## util (planned database phase)

Common utility classes such as `HashUtil` and `DatabaseUtil`. Not present today.

---

## config

Application configuration (`AppConfig`).

---

## exception

Custom application exceptions. Current: `ChatModelException`, `ContextLimitException`, `NoteStorageException`.

Planned for the database phase:

```
exception
    NoteIndexingException
```

`NoteIndexingException` will represent failures during semantic indexing, letting the UI show a meaningful message while note editing continues normally.

# 22. Conclusion
